## D-004 (2026-11-11) — `geography_vintage` is the canonical county filter
Current-county universe = `county_master.geography_vintage == "2024"` (3,144 rows). Verified: filtering `county_decade` 2020 by this set reproduces the Census 2020 count of 331,449,281 exactly. All aggregations must apply this filter.

## D-005 (2026-11-11) — Census anchor years carry no components of change
`county_year` 2010 and 2020 rows are census-count anchors; components of change exist only for estimate years. Derived migration/birth-death rates will never be computed across an anchor boundary without vintage-aware handling (`popest_vintage` column distinguishes the two series).

## D-006 (2026-11-11) — 2024 election file is provisional
2024 county returns come from an unofficial GitHub compilation (flagged in README gap #3). Under the guardrails no finding may depend on election data at all — recorded for completeness.

## D-007 (2026-11-11) — Election/power tables fenced off
`county_election`, `state_decade_power`, `national_power_summary`, and `pres_margin_rd_*` are loaded as read-only governance context. They are excluded from the RQLI objective, optimizer features, and any agent segmentation per hard constraint `political_variables_excluded`. This fence will be enforced in code (column-level denylist in the harness), not by convention.

## D-008 (2026-11-11) — Income/poverty uncertainty carried, not collapsed
SAIPE 2023 poverty and median income enter the synthetic population as 90% CI intervals (`*_ci90_lo/hi`), sampled within rather than fixed at the point estimate, per prompt Section 2.

## D-009 (2026-11-11) — Hospital table is a location source, not geometry
`facility_hospital` has addresses, no coordinates. Geocoding happens in Tier B; until then hospital positions are `derived` and hospital-count validation uses the name/county match (97.4% first-pass rate).

## D-010 (2026-11-11, Tier B pilot 1) — Open-Meteo ERA5 substitutes NOAA 1991–2020 normals

## D-011 (2026-11-11, Tier B pilot 1) — USDA CDL doubles as land cover
NLCD (mrlc.gov) unreachable. **Assumption:** CropScape CDL 2023 (30 m) serves as the land-cover layer; it is crop-focused, so non-ag classes are coarser than NLCD. Tagged `observed` with the limitation noted in the layer `_meta.json`. *Invalidated by:* mrlc.gov access.

## D-012 (2026-11-11) — USD stages are authored in /tmp, then copied

FEMA NFHL (hazards.fema.gov, msc.fema.gov) unreachable; no substitute flood layer was invented. Flood risk enters only when NFHL (or another authoritative source) is fetchable. Any flood-related experiment before then is blocked, not approximated.

## D-015 (2026-11-11) — Unplaced water systems stay unplaced

## D-016 (2026-11-11) — Overlays drape on observed terrain
Stage and viewer place every overlay (roads, rail, hydrology, power, boundaries, buildings, bridges, facilities) at DEM-sampled ground height (stage 1:1; viewer adds ×4 vertical exaggeration as a display aid, clearly labelled). Mesh cells outside the county-buffer clip polygon are filled by GDAL `fillnodata` interpolation and tagged `derived` in layer metadata; the 20 m payload GeoTIFF retains true nodata. First build had nodata→0 pits (fabricated 0 m) — fixed and recorded here so it stays fixed.

## D-017 (2026-11-11, Tier B pilot 2) — CropScape outage; Planetary Computer CDL fallback
CropScape GetCDLFile (nassgeodata.gmu.edu) began returning 404 on all API paths on 2026-11-11 (it had worked the previous evening). `fetch_cropland.py` now tries CropScape first and falls back to Microsoft Planetary Computer `usda-cdl` (`cropland_<year>_*` items, asset key `cropland`; the `cultivated_*` items are a derived mask and are NOT used). PC coverage ends at CDL 2021, so fallback vintages may lag the anchor year — recorded in the layer `_meta.json`. *Invalidated by:* CropScape service restoration.

## D-018 (2026-11-11, Tier B pilot 2) — overpass.osm.ch mirror is corrupt; empty answers are data poison
The osm.ch Overpass mirror returns HTTP 200 with zero elements and a bogus timestamp for bboxes known to contain data — an empty answer is worse than a loud failure because it looks like "no features". It is removed from the endpoint list (private.coffee + kumi.systems only, 5-attempt backoff). Waterways queries that still fail write an empty layer by design: NHD is the manifest hydrology source. **General rule now encoded in fetchers: a fetched layer that is unexpectedly empty must be treated as suspect, not as ground truth.**

## D-019 (2026-11-11, Tier B pilot 2) — /mnt mount intermittently drops freshly written files
Four files across two builds vanished from `/mnt` after successful writes (siblings written seconds apart survived). `build_county.py` now declares expected payload globs per step (`EXPECT`), verifies after every step, retries the step up to 3×, and calls `os.sync()`. County-file globs are FIPS-specific so a surviving state-level sibling (`eia860_plants_ID.csv`) cannot mask a dropped county file.

*Refinement (2026-11-12, pilot 3):* drops are nondeterministic even with zero concurrent writers — a verified write can vanish within ~8 s and need multiple rewrites before it sticks (observed on `eia860_plants_54047.csv`, a header-only zero-plant CSV). Concurrent writers to the same path make drops near-certain, so: one build at a time per county, fetchers self-heal (verify + rewrite up to 5x before exit), and build_county's EXPECT check remains the final net.

## D-020 (2026-11-11, Tier B pilot 2) — Generalization bugs found by pilot 2 (fixed at the source)
Two pilot-1 constants survived parameterization and were caught only because pilot 2 rendered wrong: (a) the viewer terrain axis projection used hardcoded Thurston reference lon/lat (−96.5, 42.0), shifting Teton's grid +104 km in ENU-y so the camera framed an empty origin; (b) the DEM drape fallback defaulted to 340 m (Thurston elevation), which would bury unplaceable Teton overlays ~1.2 km under the terrain — it now samples the county centroid. **Rule: every per-county constant lives in `county_config.py` or is derived from the payload; a literal number in a build script is a bug.** Viewer template also had a use-before-declaration (`EXAG` referencing `terrMin/terrMax` before the `let`) that crashed the whole scene script; fixed by reordering.

## D-021 (2026-11-11, Tier B pilot 3) — Terrain fallback to 3DEP 1 arc-second via Planetary Computer under egress throttle
Sandbox egress dropped to ~15 KB/s globally on 2026-11-11 evening; TNM whole-tile downloads (~400 MB each) would take ~7 h per tile. **Fallback:** `fetch_terrain.py` probes sustained throughput after 90 s; below 45 KB/s it aborts and window-reads USGS 3DEP 1 arc-second (~30 m) COGs from the Planetary Computer `3dep-seamless` collection — same USGS program, same clip, payload stays at native ~30 m (`dem_<fips>_30m.tif`), source CRS EPSG:4269 treated as 4326 (<2 m datum shift, below the pixel). Partial TNM downloads write to `.part` and are renamed on completion, so an interrupted download can never masquerade as a complete tile. Counties built on the fallback say so in layer meta and the validation sheet. *Invalidated by:* network recovery — a healthy-network rebuild re-fetches at 1/3 arc-second.

## D-022 (2026-11-12, Tier B pilot 4) — Overpass transport: curl GET; Python TLS is reset
Overpass died mid-build again (private.coffee read-timeouts, kumi.systems 504s). Diagnosis: overpass-api.de 406s POST from this sandbox but answers GET with `?data=`; and the egress middlebox resets CPython's TLS handshake (`SSL: UNEXPECTED_EOF_WHILE_READING` in 0.4 s) while `curl` succeeds on the identical query and host (verified with current `timestamp_osm_base`). `fetch_osm.py` `run()` now shells out to `curl -sS -G --data-urlencode` first per endpoint and falls back to urllib; endpoint order is api.de → private.coffee → kumi.systems. All 10 themes then fetched in one pass (schools 9, healthcare 2, power 40, places 29, water 4, waterways 86, food_shops 1, bridges 68).

## D-023 (2026-11-12, Tier B pilot 4) — Portal-mount drop escalation: stage in /tmp, settle-and-heal, cursed-path escape
The /mnt drop behavior (D-019) escalated: `nhd_waterbodies_20019.geojson` vanished after FOUR consecutive verified recopies, ~10 s apart each — the portal's async delete queue appears to stick to a path; and `eia860_plants_20019.csv` flip-flopped (present at fetcher start → gone at EXPECT seconds later → present again next attempt), which defeated fetch_grid's early-exit skip (stale `exists()`). Fixes now in fetchers: (a) payloads written to `/tmp/ruralsim_staging/<fips>/` (local ext4, reliable) then `shutil.copy2` to /mnt; (b) a settle-and-heal phase watches 12 s rounds and recopies casualties from staging — copies shielded with try/except so a mid-copy portal ENOENT just defers a round — requiring TWO consecutive stable rounds before exit; (c) if one path drops ≥5× it is cursed and the file is healed once under a glob-compatible alternate name (`nhd_waterbodies_20019_r.geojson`, recorded in `layers_raw/_healed_renames.json`) — allowed only where every downstream reference is a glob; (d) fetch_grid's early-exit-on-present was removed (regenerating CSVs from the /tmp zip cache is cheap; only the downloads are cached-skipped). Related correctness fixes caught this build: pandas NaN is truthy, so `r.get("city_name") or r.get("city_served")` returned "NAN" and placed 0/11 water systems — an `_s()` NaN guard places 10/11 now; CDL class names corrected to the official map (24 = winter wheat, not durum; 26 = dbl crop winwht/soybeans, not oats) — pixel values were always correct, labels fixed in code and 20019 `_meta.json`.

## D-024 (2026-11-12, Tier B pilot 5) — DEM window-clipping bug cropped ALL pilot terrains; coverage now validated
Pilot 5's closeup render showed the terrain mesh ending mid-county. Root cause in `fetch_terrain.py read_windows`: `from_bounds(buffered_bbox, tile_transform)` yields windows that overhang partially-overlapping 1° tiles; rasterio `read(boundless=False)` silently CLIPS such windows, but `window_transform()` was taken from the UNCLIPPED window, so clipped arrays were mis-anchored at the bbox corner and the mosaic collapsed to the last fully-inside tile. Every pilot DEM was cropped where the buffer crosses a tile edge (lat/lon coverage: Thurston 84%/99.7%, Teton 92%/97%, McDowell 100%/93%, Chautauqua 85%/86%, Wilcox 59%/78%). Elevation min/max validation passed throughout — **statistics cannot catch a spatial crop**; render review did. Fix: intersect each window with the tile extent before reading and take the transform from the clipped window. `validate_county.py` gains a "terrain coverage of county polygon ≥99%" check (bbox coverage AND rasterized valid-cell coverage). All five pilot terrains were refetched (full 1/3″ TNM quality — the egress throttle had lifted, so McDowell upgrades from the 30 m D-021 fallback) and all five stages rebuilt. **Rule: any world layer must validate spatial coverage, not just value statistics.**

## D-025 (2026-11-12, post-pilot) — Experiment harness v1, two screening runs, improve-quality-of-life skill
Harness lives in `tools/harness/`: `denylist.py` enforces `political_variables_excluded` in code at every data load (county_master.csv's `pres_margin_rd_*` columns are stripped on read, D-007); `households.py` generates synthetic populations (locations derived from OSM building centroids + jitter, incomes lognormal-calibrated to county median/poverty — synthetic people only, no address-level records, household count capped by mapped-building coverage, which propagates the known OSM rural-buildings gap); `roads.py` builds a networkx graph from the observed OSM layer with assumed class speeds; `engines.py` computes baseline RQLI indicators from observed geometry only (care/school travel via Dijkstra, bridge detours by removing NBI-poor edges) with everything unfetchable tagged `assumed` and omitted indicators left out of the geometric mean rather than filled; `constraints.py` checks all six hard constraints; `run_experiment.py` writes immutable ledger records to `experiments/ledger/<EXP-ID>/`.
